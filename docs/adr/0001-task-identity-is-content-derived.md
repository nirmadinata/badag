# Task identity is content-derived

Task IDs are derived from a task definition's name and behavior source rather than assigned per DAG or per registration. The behavior source is the kind-specific field that determines what the task does: a regular task's `fn` source, a sensor's `predicate` source, a branch's `choose` source, a short-circuit's `condition` source, a delay's `durationMs`, or a trigger's target DAG and wait flag. Definitions with the same name and behavior source share one task ID across DAGs, making registration idempotent by task ID, while task names remain the unique human-readable lookup name inside a DAG. The trade-off is deliberate: changing the behavior source creates a new identity. Description, config, trigger rule, and sensor polling interval do not affect identity. A task ID that matches an existing task with the same name reuses it; a match with a different name is rejected as a collision (`Task ID "<id>" already exists`).
